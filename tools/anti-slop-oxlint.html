anti-slop (dmmulroy, Oxlint rules)

AI가 짜는 TypeScript/JavaScript에서 흔한 '근거 없는 형 단언', '불필요한 filter→map 중복' 같은 패턴을 거부하는 Oxlint 규칙 세트를 내 프로젝트에 복사해 설정해 주는 스킬입니다.

이런 분께

개발자용. Oxlint를 쓰는 TypeScript 프로젝트에서만 의미가 있고, 제작자 취향이 강하게 반영된 규칙이라 팀 기준에 맞게 고쳐 쓰라고 안내합니다

사용 예시

  • "이 저장소에 anti-slop 린트 규칙 설치하고 설정해 줘"
  • "로컬 수정은 유지하면서 anti-slop 최신 버전으로 업데이트해 줘"

깃허브 원문 설명 한글판

이게 뭔가요?

근거가 약하고 신호가 적은 TypeScript/JavaScript 패턴을 거부하는 주관적인 Oxlint 규칙 세트입니다. 제작자가 자기 일·프로젝트·팀에 쓰는 규칙이고 보편적 코딩 표준을 노리지 않는다고 밝힙니다. npm 패키지가 아니라 '복사해서 내 저장소에 넣고(vendored) 읽고 팀 기준에 맞게 바꾸라'는 방식이며, 함께 제공되는 에이전트 스킬이 첫 복사와 설정을 맡습니다.

규칙 예시

no-array-filter-map(filter 뒤 map 같은 즉시 배열 패스 연속 거부, 지연 반복자 파이프라인은 허용), no-reduce-accumulator-copy(reduce 안에서 누산기 복사 거부), no-chained-type-assertions(근거를 꾸며 내는 중첩 as 단언 거부, as const 연쇄는 허용), no-conditional-empty-object-spread(필드 생략용 조건부 {} 스프레드 보고, 자동 수정 없음), no-known-value-widening(알려진 값을 unknown·object로 넓히는 것 거부). Effect 라이브러리를 쓰는 저장소용 선택 규칙 그룹도 있습니다.

쓰는 법

npx skills add dmmulroy/anti-slop --skill install-anti-slop 로 스킬을 설치한 뒤 에이전트에게 '이 저장소에 anti-slop 설치·설정해 줘'라고 합니다. 플러그인을 복사하고 기존 Oxlint 버전에 맞는 의존성을 설치하고 린트 설정에 병합해 모든 일반 규칙을 켜고 검증합니다. 업데이트는 '로컬 수정을 유지하며 anti-slop 업데이트'라고 요청하면 3-way 병합으로 처리하고 강제 덮어쓰기는 하지 않습니다. --list 로 스킬 목록을 볼 수 있습니다.

주의할 점

Oxlint를 쓰는 TypeScript 프로젝트가 아니면 의미가 없습니다. 개발자용입니다.
