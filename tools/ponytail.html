사용 예시

  • 너무 과격하면 "/ponytail lite", 코드베이스가 괘씸하면 "/ponytail ultra", 끄려면 "/ponytail off".

깃허브 원문 설명 한글판

포니테일이란?

회사에 버전 관리 시스템보다 오래 있었던 그 고참 개발자를 아시죠. 긴 머리, 타원형 안경. 당신이 50줄짜리 코드를 보여 주면 아무 말 없이 한 줄로 바꿔 놓습니다. 포니테일은 그 사람을 AI 에이전트 안에 넣은 것입니다.

정체는 '프롬프트 하나'입니다. skills/ponytail/SKILL.md 파일 하나가 전부이고, 저장소의 나머지는 이 프롬프트를 여러 AI 에이전트(Claude Code, Codex, Cursor 등 20개)에 꽂아 주는 어댑터입니다.

숫자로 보면

같은 Claude Code(Opus 5.5)로 39개 과제(실제 FastAPI+React 저장소 포함)를 5번씩 돌려 비교했습니다. 포니테일 5를 켰을 때 코드 -53%, 시간 -41%, 비용 -26%, 토큰 -45%.

그런데 품질은 오히려 올랐습니다. 위험한 로직(분기·반복·돈·보안)의 98%가 테스트와 함께 나왔습니다(안 켰을 땐 68%). SQL 주입·경로 탈출·토큰 위조 같은 보안 과제 30회는 전부 통과. 블라인드 비교에서 이전 버전을 110 대 67로 이겼습니다.

원칙: 적게 쓰되, 게으르지는 않게

규칙은 '토큰 최소화'가 아닙니다. '과제에 필요한 것만 쓰고, 검증·오류 처리·보안·접근성은 절대 깎지 않는다'입니다. 코드가 작아지는 건 필요한 것만 남겨서이고, 비용과 속도는 부수 효과입니다.

분기·반복·파서·돈·보안이 들어간 로직에는 작은 테스트 하나를 반드시 남깁니다. 모든 답 끝에 '무엇을 건너뛰었고 무엇을 확인하지 않았는지, 알아야 할 위험'을 적습니다.

설치와 명령

Claude Code에서 두 줄: /plugin marketplace add DietrichGebert/ponytail → /plugin install ponytail@ponytail. 딸깍은 이 두 줄을 대신 실행합니다. 설치되면 매 세션 자동으로 켜집니다.

/ponytail [lite|full|ultra|off] 강도 조절, /ponytail-review 바뀐 코드 검토(버그·보안·부하·테스트 없는 위험 코드·느린 경로·잘라낼 것), /ponytail-audit 저장소 전체 점검, /ponytail-debt 미뤄 둔 'shortcut:' 주석을 장부로 모으기, /ponytail-gain 절감 점수판.

주의

제작자는 "깃허브 DietrichGebert/ponytail 과 npm @dietrichgebert/ponytail 에서만 받으라"고 말합니다. 포니테일은 .exe나 .dll 파일을 절대 포함하지 않으며, 그런 게 들어 있는 복제판은 제작자 것이 아닙니다. 설정 파일은 필요 없고(선택 사항만 있음), MIT 라이선스입니다.
